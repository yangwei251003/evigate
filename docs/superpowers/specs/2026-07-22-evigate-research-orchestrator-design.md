# EviGate research-orchestrator design

## Decision

Build a modular, evidence-first research-orchestration Skill. It must be usable by Codex first and portable to other agent environments through declarative adapters. The initial system targets empirical AI and systems research; its domain adapters are deliberately small, schema-driven extensions rather than separate workflows.

## Options considered

1. One large prompt-only Skill: fast to write, but weakly testable and unsafe for experiment/result provenance.
2. A monolithic application: powerful, but couples model, search, execution, and UI before the scientific workflow is validated.
3. A concise orchestrator plus explicit artifacts and deterministic validators: selected. It supports incremental extension, preserves human authority at gates, and makes a paper-ready audit trail possible.

## Architecture

```text
Skill router
  -> project state + phase gate
  -> evidence registry / protocol / experiment / analysis / drafting modules
  -> deterministic validators
  -> immutable artifacts and claim-evidence links
```

The portable package contains:

- `skills/evigate-research-orchestrator/`: the master Skill, templates, and schema references.
- `src/evigate/`: a dependency-light Python CLI that creates and validates project state, evidence records, run manifests, and claim links.
- `adapters/`: agent-specific instructions and domain-specific constraints.
- `benchmark/`: a deliberately small, public synthetic benchmark used only for initial system validation.
- `paper/`: a manuscript whose quantitative statements are generated from registered benchmark runs.

## Phase model

The system implements these logical stages: capability and repository audit; research question; evidence discovery and verification; protocol freeze; data/environment; baseline reproduction; experiment; analysis; claim-evidence mapping; drafting; integrity review; peer review; revision; final package; archive.

A stage can advance only when its required artifacts validate. A `PASS_CANDIDATE.json` may be generated by checks, but `PASS.json` requires an explicit human approval tied to a commit. The first implementation covers capability, evidence, protocol, experiment, analysis, claim mapping, and drafting gates; later stages remain explicit extension points.

## Evidence and safety model

- Treat URLs, papers, datasets, prompts, and tool output as untrusted input.
- Assign every source a Source ID and verification status. Only verified sources may support manuscript claims.
- Assign every experiment a Run ID and immutable manifest before execution. The manuscript may consume only registered derived results.
- Mark numerical statements as `measured`, `simulated`, or `illustrative`; never present synthetic results as real-world measurements.
- Keep autonomous operation bounded by a task budget, a stop condition, and risk escalation rules. Human approval is mandatory for protocol freeze, formal-test opening, publication package, and irreversible scope changes.

## Auditable self-improvement boundary

After a run or audit, the Skill may inspect registered failures, unresolved evidence gaps, gate refusals, and reviewer findings to draft an `ImprovementProposal`. Each proposal identifies the triggering artifact, affected component, expected benefit, risk, validation test, and whether it touches a frozen artifact. The CLI only validates and summarizes proposals; it never accepts, applies, or deletes them. An agent may change its next non-frozen task plan using an accepted proposal, but changing a Skill, adapter, protocol, benchmark, or formal output requires a reviewable Git change and human approval. This creates an evidence-backed improvement loop without self-modifying scientific records.

## Initial validation study

The first paper is a systems-and-benchmark study, not a claim of a finished general scientific agent. It will compare a direct-drafting baseline with the EviGate workflow on a small, synthetic, transparent set of research packets containing planted evidence/provenance defects. The registered outcomes are detection/containment of unsupported claims, manifest completeness, and escalation behavior. It will clearly report that synthetic tasks measure workflow reliability, not real-world publication quality.

## Acceptance criteria for the first implementation phase

1. The Skill is discoverable as `evigate-research-orchestrator` and remains under 500 lines with referenced detail kept outside it.
2. The CLI validates state transitions, required evidence fields, run-manifest completeness, and claim-to-evidence links deterministically.
3. Test fixtures cover valid and invalid records, including missing evidence, nonexistent source status, and unregistered quantitative claims.
4. A small registered benchmark can be executed without external credentials and preserves all successes and failures.
5. Improvement proposals are validated, traceable to their triggering artifacts, and cannot silently alter frozen materials.
6. The manuscript contains no results until the benchmark artifacts and audit are present.

## Out of scope for this increment

- Autonomous execution of arbitrary LLM-generated code.
- Automatic submission, publication, or communications with journals.
- Any claim that one benchmark establishes reliability across every discipline.
