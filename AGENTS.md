# Repository operating rules

1. Read `PROJECT_STATE.yaml` before making project changes.
2. Do not start a later phase without a human-approved `PASS.json` tied to a Git commit.
3. Never overwrite formal runs, manifests, frozen configurations, seeds, or test sets.
4. Every quantitative manuscript value must trace to a Run ID, raw artifact, configuration, seed, environment lock, and commit.
5. Every scholarly claim must trace to a verified Source ID; discovery metadata is not verified evidence.
6. Keep GPL and unclear-license code outside the Apache-2.0 core and record third-party reuse.
7. Do not commit credentials, private PDFs, cloud keys, or personal telemetry.
8. Preserve failures and negative results; never silently exclude or repair formal runs.
